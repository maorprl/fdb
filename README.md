# Finder / FDB — מסמכי סכמה ללימוד SQL

סביבת BigQuery: `fdb-sql-lab.fdb`. התיעוד מתייחס ל־**16 טבלאות ליבה** בלבד ומבוסס על בדיקות שנעשו בעבר, ללא בדיקות חדשות.

| קובץ | מה הוא מכיל |
| --- | --- |
| [mapping_v0.6.md](mapping_v0.6.md) | מסמך המיפוי המלא, Key Audit, חריגות וסייגים |
| [erd.md](erd.md) | תרשים ERD קריא ב־GitHub (Mermaid) |
| [relationships.csv](relationships.csv) | מטריצת קשרים ברמת שדות, ספירות ורמות אימות |
| [schema_columns.csv](schema_columns.csv) | קטלוג 343 עמודות בכל 16 טבלאות הליבה: טבלה, מיקום, שם שדה, טיפוס ו־nullable |

**חשוב:** `id` ייחודי ולא NULL בכל 16 הטבלאות שנבדקו, אך אין אילוצי PK/FK פיזיים מוצהרים ב־BigQuery. הקשרים הם לוגיים; חלקם מכילים הפניות חסרות או מותנים בסוג אירוע. אין FK ישיר מאומת בין שני מודלי הגיוסים, או בין שני מודלי החדשות. אל תניח שקשר לא מתועד קיים.

מאגר זה הוא תיעוד מבני לצורכי תרגול, **לא** העתק של מסד הנתונים ולא שכבת נתונים נקייה. אין כאן נתונים גולמיים או פרטי גישה.

מומלץ להשתמש במיפוי ובמטריצה כבסיס לתרגילי SQL, ולהקפיד על Grain, קרדינליות ו־fan-out בכל JOIN.

מקור קטלוג העמודות: ייצוא `INFORMATION_SCHEMA.COLUMNS` קודם של 21 טבלאות (342 שדות), שממנו נלקחו 15 טבלאות הליבה (316 שדות), בצירוף JSON הסכמה של `New_Member` (27 שדות) לאחר העלאתה. טיפוס `INTEGER` בקובץ `New_Member` נורמל ל־`INT64`, שהוא השם המקובל ב־GoogleSQL. זהו שילוב של שני snapshot-ים מתועדים ולא בדיקה חיה חדשה של BigQuery.
